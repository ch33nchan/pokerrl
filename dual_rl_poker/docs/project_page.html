MARM-K Poker Research Stack

A publication-ready environment for studying meta-adaptive regret minimisation in two-player poker, combining differentiable policy optimisation, bandit-consistent scheduling, and deterministic Rust rollouts with full experiment automation.

CPU & GPU Ready Rust & OpenSpiel Backends Sublinear Scheduler Regret

Research Motivation

Modern regret-matching poker agents either rely on large CFR-style tables or on neural policy gradients that lack late-stage stability. MARM-K addresses this gap by learning a state-conditioned gate over heterogeneous experts that can pivot between neural exploration and tabular exploitation in response to local exploitability estimates. The stack is designed for researchers who need deterministic, publication-grade evidence without GPU-heavy infrastructure.

Key Ideas

  • Bi-level meta-objective that maximises exploitability reduction through short unrolls.
  • Regret-matching target that bounds scheduler regret at O(√(T log K)).
  • Anytime handoff into compact CFR heads when subgames stabilise.

Supported Games

  • Kuhn Poker (deterministic rollouts).
  • Leduc Poker (6-card and 10-card variants).
  • Extendable to other two-player, zero-sum imperfect-information games.

Outputs

  • JSON/CSV/TeX artefacts per run with manifests for plotting.
  • Parity reports between Rust and OpenSpiel simulations.
  • ICML-style manuscript scaffold and TikZ architecture diagram.

System Architecture

Learning Loop

  • Trajectory Collection: Mix experts according to the gate distribution to sample episodes from either backend.
  • Expert Updates: Actor/regret heads optimise ARMAC objectives; risk-averse and exploratory heads use temperature adjustments; CFR heads update via tabular regret matching within marked clusters.
  • Meta Step: Shared-trajectory approximate best responses evaluate the counterfactual improvement of each expert. Gradients flow only into the gate parameters.
  • Bandit Tracking: Clustered utilities accumulate regret-adjusted advantages to align the gate with the regret-matching target distribution.
  • Anytime Handoff: When rolling exploitability dips below the configured threshold for a cluster, gate logits are biased toward the CFR head and actor updates for that cluster pause.

Backend Coordination

  • Identical Python APIs wrap the Rust and OpenSpiel simulators, making the backend switch transparent to the training loop.
  • Parity checks periodically replay seeds across both backends to ensure bitwise-equivalent payoffs.
  • Device selection propagates to all tensors, enabling CPU, CUDA, or Apple MPS execution through a single --device flag.

Algorithm Internals

Expert Gate

  • Context features include phase-of-play, running loss EMAs, exploitability deltas, and iteration progress.
  • Outputs a softmax distribution over five experts with probability clamps to maintain numerical stability.
  • Entropy regularisation and KL penalties prevent premature collapse while matching the bandit target.

Approximate Best Response

  • Shared RNG ensures each expert evaluation reuses the same trajectories as the cached baseline.
  • Budget parameter --br-budget governs the number of rollouts per update; 64 is the recommended research default.
  • Utilities are clipped to [-5, 5] and normalised per cluster before contributing to gate updates.

State Clustering

  • Configurable via --state-cluster, defaulting to round+position+pot for a compact yet informative partition.
  • Each cluster maintains running exploitability estimates and bandit utilities to enable targeted handoffs.
  • Missing-cluster diagnostics surface in telemetry to guard against sparse data regimes.

End-to-End Workflow

  1. Environment Preparation: create the virtualenv, install Python dependencies, and build the Rust crate (optional if only OpenSpiel is needed).
  2. Single Run Shakeout: run run_real_training.py with --backend rust and --backend pyspiel to confirm both pipelines produce logs under results/.
  3. Suite Execution: invoke scripts/run_poker_suite.py --backend both to generate all benchmarks (MARM-K variants plus CFR anchors) across seeds.
  4. Aggregation & Plots: execute generate_results.py and create_plots.py to refresh combined manifests, LaTeX tables, and PNG figures.
  5. Manuscript Integration: import tables/plots into docs/paper_draft.tex and rebuild the PDF with latexmk -pdf.

Each run writes JSON summaries (metrics.json), per-iteration CSV logs (history.csv), and LaTeX tables (summary.tex) into results/<experiment>/<game>/<policy>/seed_*/. Aggregated artefacts collect inside results/combined/ for fast plotting.

Evaluation Protocol

Core Metrics

  • Exploitability estimates derived from cached approximate best responses.
  • Gate entropy and per-expert selection frequencies to quantify scheduler diversity.
  • Empirical scheduler regret computed from bandit utilities on a log–log scale.

Experiments

  • E1: Compare meta-learned λ against fixed and loss-difference schedules.
  • E2: Incrementally add experts (2 → 5) to evaluate contribution to exploitability.
  • E3: Stress-test the anytime CFR handoff across patience/threshold settings.
  • E4: Sweep approximate BR budgets to trade off runtime and stability.
  • E5: Validate Rust/OpenSpiel parity, throughput, and determinism.

Reproducibility & Extensibility

Determinism

  • Global seed propagates to Python, NumPy, PyTorch, Rust, and OpenSpiel components.
  • Rust backend supports parity playback and emits warnings on divergence beyond 1e-7.

Extending the Stack

  • Add new experts by registering them inside algs/scheduler/gate.py and wiring update rules in the training loop.
  • Introduce new games by implementing the environment interface for the chosen backend and defining cluster features.
  • Augment diagnostics by editing generate_results.py to compute additional summary statistics.
